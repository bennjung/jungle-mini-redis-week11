# 디버깅에서 확인한 원칙

## 전체 마감은 예약 콜백뿐 아니라 작업 허용·응답 복귀에서도 확인한다

- 확인 경로: `tests/scenario_03_performance/counter.groovy`의 `M3Coordinator.beginCall`, `onTotalLimit`, `finishCall`.
- 실제 N=10,000 파일럿에서 전체 120초가 지난 뒤에도 콜백이 실행되기 전에는 요청을 하나 더 허용했다. 콜백이 그 요청의 결과 결정 시각을 이전 마감으로 소급해 `decision_ns < start_ns`를 만들었다.
- 예약 감시기는 원하는 시각에 반드시 실행되는 실시간 보장이 아니다. 작업 허용과 결과 판정 시 단조 증가 시계로 실제 마감을 다시 검사해야 한다.
- 응답이 마감 전에 도착하고 분류만 늦은 경우와, 응답 자체가 마감 이후인 경우를 구분한다. 요청별 한도와 전체 한도 중 먼저 도달한 한도를 적용한다.
- 불변 조건: 전체 마감 후 새 호출 시작 금지, 기록의 시작≤결정, 늦은 응답으로 실패를 성공으로 바꾸지 않음. 콜백을 의도적으로 늦추는 회귀로 검증한다.
- 실패한 원자료는 수정·삭제하지 않는다. 종료 불명확 표식은 다음 초기화를 차단하며, 도구 수정만으로 재실행 승인이 생기는 것은 아니다.
