# 4. API 응답 재사용·만료·수동 무효화

## 상태와 근거

- 사용자 시나리오의 분리는 합의되었으며, 아래 테스트 시나리오는 검토 초안이다. 만료 및 재사용 정책은 미확정이다.
- 요구사항 원문: [phase.md](../phase.md)의 간단한 API 응답 저장·활용, 만료된 값 요청 처리, 사용자에 의한 데이터 무효화.
- 공통 개발 흐름: [AGENTS.md](../../AGENTS.md).
- 선행 문서: [1. 외부에서 값 보관·조회·폐기](../scenario_01_storage/01-storage-scenario.md).
- 카운터 시나리오와 구별되는 응답 저장·활용 사례다. 카운터 완료만으로 이 요구사항을 충족했다고 보지 않는다.
- 저장소에는 API 응답의 JSON을 UTF-8 글자로 보관한다. 저장소가 JSON 구조를 해석하거나 객체 타입으로 바꾸지 않는다. 키는 1~256바이트, 문자열 `value`는 0~65,536바이트이며 세부 계약은 문서 1을 따른다. 실제 예제 응답이 이 상한 안에 있는지 확인한다.

## 사용자 시나리오

간단한 API를 사용하는 사용자는 아직 유효한 응답을 미니 Redis에서 재사용한다. 보관 기한이 지났거나 사용자가 무효화한 응답은 유효한 저장 응답으로 재사용되지 않아야 한다.

## 범위와 완료 판단

- 포함: API 응답 저장·재사용, 만료된 값의 요청 처리, 명시적인 수동 무효화.
- 제외: 장애 복구, 여러 원본 사이의 자동 동기화, 재고·호출 제한 정책.
- 완료 판단: 실제 외부 사용 경로에서 세 동작을 각각 확인하고, 미사용 경로와 저장 응답을 활용한 경로를 구분할 수 있다.
- 수동 삭제와 시간 만료는 별개의 검증 대상이다.
- 만료된 값을 사용하지 않는 시점과 메모리에서 실제 제거하는 시점은 같은 것으로 가정하지 않는다.

## 테스트 시나리오 초안

### S4-01. 보관한 API 응답 재사용

- 사전 상태: 대상 응답이 미니 Redis에 없다. 원본 API의 예제 응답 내용은 `{"message":"hello"}`이며, 저장소에는 이 내용을 글자로 저장한다.
- 입력·행동: 원본 API 응답을 받아 저장하고, 아직 유효한 동안 같은 응답을 다시 요청한다.
- 검증 시점: 두 번째 요청의 응답 수신 후.
- 기대 결과: 저장한 응답 내용이 재사용된다.
- 유지 조건: 응답 내용이 같다는 사실만으로 재사용을 입증하지 않는다. 저장소에서 얻은 값이 사용되었음을 관찰할 수 있어야 한다.
- 미정: 예제 API, 응답 키의 기준, 응답 유효 기간, 재사용 여부의 관찰 방법과 원본 호출 생략 보장.

### S4-02. 만료된 응답을 재사용하지 않음

- 사전 상태: 예제 응답을 유효 기간과 함께 저장했다.
- 입력·행동: 유효 기간이 지난 시점에 해당 응답을 요청한다.
- 검증 시점: 만료 이후 요청의 응답 처리 완료 시.
- 기대 결과: 만료된 저장 응답을 유효한 값으로 재사용하지 않는다.
- 유지 조건: 만료 이후 같은 값을 요청해도 이전 저장 응답이 유효한 것으로 되살아나지 않는다.
- 미정: 기간과 시작 시점, 정확한 만료 경계, 만료 시 응답 및 원본 재조회 여부, 시간 진행을 재현하는 방법.

### S4-03. 사용자가 응답을 수동 무효화

- 사전 상태: 예제 응답이 저장되어 있고 아직 만료되지 않았다.
- 입력·행동: 해당 응답을 무효화한 뒤 같은 응답을 다시 요청한다.
- 검증 시점: 무효화 성공 후 새 요청의 응답 처리 완료 시.
- 기대 결과: 무효화 이전의 저장 항목을 재사용하지 않는다.
- 유지 조건: 다른 키에 저장된 응답에는 영향을 주지 않는다.
- 주의: 원본 재조회 결과가 이전 응답과 같을 수 있으므로 응답 내용만으로 무효화를 입증하지 않는다.
- 미정: 무효화 후 응답 처리와 관찰 방법. 저장소의 삭제 계약은 문서 1과 일치시킨다.
- 저장소의 `delete(key)` 결과: 항목이 있으면 `{"found": True, "value": 삭제한 응답 문자열}`, 없으면 `{"found": False}`다. HTTP 저장소 API에서는 각각 JSON의 `true`·`false`로 표현한다. 무효화 후 예제 애플리케이션이 사용자에게 전달할 응답은 별도 미정이다.

## 계약 확정 전에 합의할 사항

- 위 시나리오에 적힌 미정 입력·시간·응답·관찰 기준.
- 원본 API 실패와 미니 Redis 사용 실패 시 사용자에게 제공할 동작.
- 만료 직전·정확한 경계·직후의 기대 결과와 반복 무효화 처리.
- 동시 만료 요청, 진행 중인 조회·저장과 무효화의 경합을 이번 범위에 포함할지 여부.
- 계약 합의 후 정확한 시간 입력과 실패·경계 테스트를 추가한다. 현재 초안을 완성된 테스트 계약으로 취급하지 않는다.
