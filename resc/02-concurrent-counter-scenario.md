# 2. 같은 카운터의 동시 증가

## 상태와 근거

- 사용자 시나리오의 분리는 합의되었으며, 아래 테스트 시나리오는 검토 초안이다. 개별 기대 결과와 미정 사항을 합의한 뒤 구현 계약으로 확정한다.
- 요구사항 원문: [phase.md](phase.md)의 동시성 문제가 발생하지 않는 구조에 대한 검토.
- 카운터 증가는 과제 원문에 명시된 명령이 아니라, 사용자가 선택한 경합 문제를 검증하기 위한 시나리오다.
- 공통 개발 흐름: [AGENTS.md](../AGENTS.md).
- 선행 문서: [1. 외부에서 값 보관·조회·폐기](01-storage-scenario.md).

## 사용자 시나리오

여러 요청이 같은 카운터를 동시에 증가시킨다. 사용자는 요청들이 완료된 뒤 증가분이 유실되지 않은 최종값을 조회할 수 있어야 한다.

## 범위와 완료 판단

- 포함: 이미 존재하는 같은 카운터에 대한 동시 증가와 완료 후 조회.
- 제외: 재고 부족 판정, 호출 제한의 시간 구간, 증가와 삭제·만료의 경합, 장애 복구.
- 완료 판단: 모든 요청이 성공한 조건에서 초기값에 증가분을 합한 값과 최종 조회값이 일치한다.
- 조회와 저장이 각각 안전하다는 사실만으로 전체 증가 동작의 원자성을 입증했다고 보지 않는다.
- 요청 실패나 재시도가 섞인 경우는 성공한 경우의 계산식을 그대로 적용하지 않고 별도 계약을 정한다.

## 테스트 시나리오 초안

### S2-01. 단일 증가의 기준 동작

- 사전 상태: `counter:one`의 값이 `0`이다.
- 입력·행동: 해당 키에 `1` 증가 요청을 한 번 보내고 성공 응답 후 조회한다.
- 검증 시점: 증가 완료 후 조회 응답 수신 시.
- 기대 결과: 최종값은 `1`이다.
- 유지 조건: 조회만 반복하면 값은 변경되지 않는다.
- 미정: 증가 요청과 응답의 정확한 표현, 숫자 저장·조회 규칙.

### S2-02. 같은 키의 동시 증가분 보존

- 사전 상태: `counter:one`의 값이 `0`이며 다른 요청은 없다.
- 입력·행동: 같은 키에 각각 `1`을 증가시키는 요청 `100`건을 동시 진행시킨다.
- 검증 시점: 100건 모두 성공 응답을 받은 뒤 별도 조회를 완료한 시점.
- 기대 결과: 최종값은 정확히 `100`이다.
- 유지 조건: 증가분이 유실되거나 중복 반영되지 않는다.
- 실행 범위: 외부 사용 경로. 설계 후 동시 실행을 만드는 방법과 단위 테스트 호출 대상을 명시한다.
- 주의: 요청 실패가 발생하면 이 시나리오의 성공 조건을 충족하지 못한 것이다. 실패한 요청을 임의로 제외하여 통과시키지 않는다.
- 한계: 한 번의 통과만으로 모든 실행 순서에서의 안전성을 증명할 수 없다. 설계 검토와 반복·다양한 실행 조건의 검증을 함께 수행한다.

### S2-03. 기존 값에서 증가분 보존

- 사전 상태: `counter:one`의 값이 `10`이다.
- 입력·행동: 같은 키에 각각 `1` 증가 요청 `100`건을 동시 진행시킨다.
- 검증 시점: 모든 요청이 성공한 뒤 최종 조회 완료 시.
- 기대 결과: 최종값은 `110`이다.
- 유지 조건: 기존 값이 초기화되거나 덮어써지지 않는다.

## 계약 확정 전에 합의할 사항

- 없는 키의 증가, 숫자가 아닌 값, 표현 가능한 수의 범위 초과 처리.
- 요청 실패·응답 유실·재시도 시 값의 변경 여부와 중복 처리 보장 범위.
- 증가와 삭제·만료가 겹치는 동작을 이번 범위에 포함할지 여부. 제외는 안전성 보장을 뜻하지 않는다.
- 내부 처리 구조와 구체적인 호출 인터페이스는 행동 계약 합의 후 결정한다.
- 미정 동작은 기대 결과를 임의로 만들지 않고 합의 후 테스트를 추가한다.
