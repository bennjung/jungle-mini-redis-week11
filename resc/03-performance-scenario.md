# 3. 정확성을 유지한 성능 비교

## 상태와 근거

- 시나리오의 분리는 합의되었으며, 아래 측정 시나리오는 검토 초안이다. 비교 조건과 성능 판정 기준은 미확정이다.
- 요구사항 원문: [phase.md](phase.md)의 미니 Redis 사용 전후 성능 차이 비교.
- 이 문서는 사용자 기능이 아니라, 사용자가 선택한 경합 문제의 성능 가정을 확인하는 검증 시나리오다.
- 공통 개발 흐름: [AGENTS.md](../AGENTS.md).
- 선행 문서: [2. 같은 카운터의 동시 증가](02-concurrent-counter-scenario.md).

## 검증할 질문

같은 카운터의 증가분을 잃지 않고 처리하는 조건에서, 미니 Redis를 사용할 때와 사용하지 않을 때 처리량과 응답 지연이 어떻게 달라지는가?

기존 DB 방식에서도 정확한 갱신은 가능하다. 동시 요청 수만으로 DB 병목을 단정하지 않으며, 취약한 읽기·덮어쓰기 방식을 비교 대상으로 삼아 성능 우위를 주장하지 않는다.

## 범위와 완료 판단

- 포함: 같은 카운터 작업, 동일한 정확성 기준, 사용 전후 처리량·응답 지연·실패 건수 비교.
- 제외: 모든 작업에서의 성능 우위, 측정 없는 디스크 입출력·잠금 병목 단정, 장애 복구 성능.
- 완료 판단: 합의한 조건으로 양쪽을 측정하고 정확성 및 성능 결과를 함께 기록한다.
- 성능 개선이 없더라도 비교 자체는 완료될 수 있다. 문제 가설의 성립 여부와 과제의 비교 수행 여부를 구분한다.
- 해시 테이블은 평균적으로 상수 시간에 접근할 수 있지만, 이것만으로 전체 요청의 응답 지연을 보장하지 않는다.

## 측정 시나리오 초안

### S3-01. 비교 대상의 정확성 확인

- 사전 상태: 양쪽 비교 대상에서 카운터의 초기값이 `0`이다.
- 입력·행동: 양쪽에 같은 키를 `1`씩 증가시키는 요청을 각각 `100`건 동시 진행시킨다.
- 검증 시점: 각 대상의 모든 요청이 성공 응답을 반환한 후 최종 조회 완료 시.
- 기대 결과: 양쪽 모두 최종값은 `100`이다.
- 유지 조건: 한쪽의 정확성을 낮춰 속도를 높인 결과를 동등한 비교로 제시하지 않는다.
- 미정: 미사용 비교 대상의 구체적인 구성과 실행 경로.

### S3-02. 동일 작업량에서 성능 측정

- 사전 상태: S3-01의 정확성을 확인했고, 측정 환경과 부하 조건을 합의하여 기록했다.
- 입력·행동: 합의한 동일 요청 수·동시 요청 수·초기값으로 양쪽을 측정한다.
- 검증 시점: 각 측정 종료 후 최종값과 요청 결과를 확인한 시점.
- 기대 결과: 처리량, 응답 지연, 성공·실패 건수와 최종값을 양쪽 모두 기록한다.
- 유지 조건: 실패한 요청을 숨기거나, 작업량·정확성 보장이 다른 결과를 같은 조건처럼 비교하지 않는다.
- 미정: 정확한 부하 수치, 응답 지연 집계 방식, 준비 실행과 반복 횟수, 실행 순서, 환경 차이의 통제 방법.
- 주의: 이 항목은 위 입력과 조건을 확정하기 전에는 실행 가능한 계약이 아니다.

## 계약 확정 전에 합의할 사항

- 미사용 기준선, 양쪽 요청 경로와 제공하는 보장의 동등성.
- 측정 자원·환경, 정확한 입력 부하와 반복 조건.
- 성능 개선을 주장할 경우 필요한 개선 폭과 허용 실패 기준.
- 잠금 대기나 디스크 입출력을 병목 원인으로 주장한다면 필요한 별도 관찰 근거.
