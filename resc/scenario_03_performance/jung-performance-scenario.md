# 시나리오 03 성능 비교 — 검토 메모

검토 대상: [정확성을 유지한 성능 비교](03-performance-scenario.md).
작성 기준: [테스트 시나리오 초안 검토 메모](../템플릿-scenario-preparation-template.md).

기존 시나리오를 다시 작성하지 않고, 사용자와 합의한 보완 내용과 추가 합의가 필요한 항목을 구분한다. 미정 항목은 구현 계약으로 사용하지 않는다.

## 검토 메모

### 빠진 상황

- **[S3-01] 실제 숫자 타입으로 저장 — 합의됨.** Mini Redis와 MySQL 모두 초기 `value`를 실제 숫자 `0`으로 저장한다. 각각 `1` 증가 요청 100건이 모두 성공한 뒤 최종 조회한 `value`는 실제 숫자 `100`이어야 한다. 기존 초안의 문자열 `"0"`·`"100"` 기준은 이번 합의와 다르다. Mini Redis의 숫자 저장은 [S2 통합 검토](../scenario_02_concurrent_counter/02-concurrent-counter-integrated-review.md)의 저장 계약 변경과 연결하며, 테스트 준비를 위해 내부 상태에 숫자를 직접 넣어 우회하지 않는다.
- **[S3-02] 총 요청 수와 동시 요청 수 구분 — 합의됨.** 전체 실행할 요청 수와 동시에 진행할 요청 수를 별도로 기록한다. 두 수치의 구체적인 값은 미정이다. S3-01의 100건 동시 진행 조건과 S3-02의 측정 부하를 혼동하지 않는다.
- **[S3-02] 요청 실행 구간만 측정 — 합의됨.** 연결 생성과 초기 데이터 준비는 측정 전에 수행한다. 요청 실행 구간만 측정하고, 종료 후 최종 조회와 연결 종료는 측정 시간에서 제외한다. 요청 구간의 정확한 시작·종료 지점과 개별 응답 지연의 집계 방식은 추가 합의가 필요하다.
- **[S3-02] 테스트마다 새 연결 생성·종료 — 합의됨.** 테스트할 때마다 새로운 연결 객체를 생성하고, 테스트가 끝나면 연결을 종료한다. 연결을 만드는 단위가 개별 요청인지 측정 실행 한 회인지와 동시 요청에 사용할 연결 수는 아직 정하지 않았다.
- **[S3-01·02] 시간 초과는 실패로 처리 — 합의됨.** 시간 초과가 발생한 요청은 실패 건수에 포함하고, 성공 처리량에 포함하지 않는다. S3-01은 모든 요청의 성공이 조건이므로 시간 초과가 있으면 통과하지 못한다. 재시도하지 않으며, 시간 초과가 서버의 미반영이나 취소를 뜻하는 것은 아니다. 시간 초과 기준 시간은 미정이다.

### 다른 의견

- **[S3-01·02] 증가 성공 확인과 변경 직후 `value` 반환의 비교 범위 — 추가 합의 필요.** Mini Redis는 증감 성공 시 변경 직후 `value`를 반환하는 방향이다. MySQL의 `UPDATE` 성공 확인과 해당 명령의 변경 직후 `value`를 반환받는 작업 중 어디까지를 비교 대상으로 삼을지 정해야 한다. 나중에 별도로 조회한 `value`는 다른 요청이 반영된 결과일 수 있으므로 해당 명령 직후의 `value`와 같다고 가정하지 않는다. MySQL에서 이를 구현할 구체적인 방법은 아직 정하지 않는다.

### 미정 사항에 대한 생각

- **[S3-02] 실행 순서를 번갈아 반복 — 추가 합의 필요.** Mini Redis → MySQL, 다음에는 MySQL → Mini Redis처럼 순서를 바꾸는 방안을 검토한다. 이 방식 자체와 준비 실행 여부·반복 횟수·매회 초기화 조건은 아직 합의하지 않았다.
- **[S3-02] 연결 생성 단위와 연결 수.** 새 연결을 만드는 단위와 동시에 사용할 연결 수를 확정한 뒤 측정 절차에 연결한다. 현재 메모에서 연결 풀이나 연결 재사용 정책을 임의로 추가하지 않는다.
- **[S3-01·02] 남은 측정 기준.** 총 요청 수·동시 요청 수, 시간 초과 기준, TPS 계산 구간과 응답 지연 집계 방식의 구체적인 기준을 합의해야 실행 가능한 테스트 계약이 된다.

측정 경로와 저장 보장은 앞서 합의한 조건을 따르며 이번 메모에서 재검토하지 않는다. 이 메모는 합의된 보완 사항과 미정 항목의 기록이며, 기존 시나리오 전체의 테스트 계약 확정이나 구현 완료를 뜻하지 않는다.
