## 환경과 해석상 한계

- Mini Redis: 커밋 `ac8c9b2`의 고정된 서버 코드, Python 3.14.10, FastAPI 0.163.1, uvicorn 0.54.0, `workers=1`, HTTP, `h11` 0.16.0. 측정 시 `httptools`는 설치되지 않았다.
- MySQL 8.4.13: JDBC, 요청별 자동 커밋. `innodb_flush_log_at_trx_commit=1`, `sync_binlog=1`, `log_bin=1`.
- Mini Redis는 메모리 반영, MySQL은 디스크 변경 확정을 포함하며 **통신 경로와 내구성 보장이 다르다**. 모든 작업이나 같은 내구성을 가진 저장 방식의 우열을 보여주는 결과는 아니다.
- 서버·부하 생성기·MySQL은 같은 호스트에서 실행했고 다른 컨테이너도 공존했다. 단일 키 증가만 측정했으며 별도 호스트 간 통신, 혼합 읽기·쓰기, 다중 키, 장애 복구는 검증하지 않았다.
- HTTP의 TCP 연결 재사용 횟수는 측정하지 않았다. JDBC는 실행 주체별 연결 식별을 확인했다.
- 측정 조율기의 공유 잠금·기록 비용을 포함하며, 계측을 켜고 끈 비교는 하지 않았다. 5회 중앙값은 통계적 유의성을 뜻하지 않는다.
