# 03번 성능 비교 검토 메모 — 찬

이 문서는 모임 검토를 위해 작성한 개인 메모의 원래 내용을 보존한다. 이후 사용자와 합의한 비교 구성·측정 절차는 [03번 시나리오](03-performance-scenario.md)에 반영했다. 아래의 과거 미정 표시는 현재 상태가 아니며, 현재 남은 미정 사항은 해당 문서의 ‘파일럿과 남은 확정 사항’을 따른다. 개인 메모 자체를 확정 계약으로 취급하지 않는다.

## 비교 목적

- 같은 카운터의 증가분을 잃지 않는 조건에서 미니 Redis와 DBMS의 성능 차이를 확인한다.
- 미니 Redis가 어떤 상황에서 유용한지 살펴보고, 이번 구현이 느리다면 개선할 지점을 찾는다.
- 성능 개선 여부와 과제의 성능 비교 수행 여부는 구분한다. 개선이 없더라도 비교 결과는 기록한다.

## 확인할 상황

1. **정확성 확인:** 같은 초기 숫자와 증가량으로 같은 카운터를 증가시킨 뒤, 모든 요청이 성공한 경우 양쪽의 최종 숫자가 요청 횟수와 일치하는지 확인한다. 성능이 빠르더라도 증가분이 유실되면 같은 정확성을 제공한 비교가 아니다.
2. **요청이 적은 상황:** 요청이 적거나 한 번에 하나씩 들어올 때 양쪽의 응답 시간과 처리량을 확인한다.
3. **요청이 점차 몰리는 상황:** 같은 카운터에 동시에 보내는 요청 수를 단계적으로 늘려 양쪽의 처리량과 응답 시간이 어떻게 달라지는지 확인한다. 정확한 요청 수와 단계는 미정이다.
4. **처리 한계에 가까운 상황:** 요청이 몰릴 때 응답 지연, 연결 실패, 시간 초과 등 실패가 발생하는지 확인한다. 실패를 제외한 성공 결과만으로 전체가 정상 처리된 것처럼 판단하지 않는다.
5. **반복 측정:** 같은 조건을 여러 번 실행해 결과가 매번 비슷한지 확인한다. 준비 실행, 반복 횟수와 실행 순서는 미정이다.
6. **느린 구간 확인:** 전체 경로 측정에서 차이가 관찰되면 통신 대기, 요청 처리, 저장소 연산 등 관련 구간을 별도로 살펴본다. 구간별 측정은 전체 경로 비교를 대체하지 않는다.
7. **개선 전후 확인:** 느린 원인을 확인해 개선한 경우, 같은 작업과 측정 조건으로 다시 실행하고 정확성·성공과 실패·성능이 어떻게 바뀌었는지 확인한다.

## 측정과 판정에서 확인할 것

- 클라이언트가 요청을 보낸 시점부터 같은 결과의 응답을 받을 때까지 전체 시간을 측정한다. DBMS 전용 통신과 그 대기 시간도 실제 경로에 포함되면 측정에 포함한다.
- 양쪽이 같은 키·초기 숫자·증가량·요청 수·동시 요청 수와 같은 정확성 기준을 사용하는지 확인한다. DBMS도 안전한 증가 방식으로 처리해야 한다.
- 처리량과 응답 시간뿐 아니라 성공·실패·시간 초과 등 요청 결과와 최종 숫자를 함께 기록한다. 응답이 유실된 요청은 실제 처리 여부를 알 수 없으므로 단순히 미처리로 간주하지 않는다. 현재 시나리오 02에서는 자동 재시도하지 않는다.
- 양쪽의 실제 요청 경로, 실행 환경, 자원과 DBMS 설정을 기록한다. 전체 경로의 차이를 저장소 내부 연산만의 차이라고 단정하지 않는다.
- 현재 미니 Redis는 재시작 후 보관을 보장하지 않는다. DBMS의 보관·복구 설정이 다르면 같은 응답을 얻더라도 보장이 다르다는 점을 결과에 함께 기록한다.
- DBMS의 잠금이나 디스크 입출력이 원인이라고 주장하려면 성능 차이만이 아니라 별도의 관찰 근거가 필요하다.

## 기존 초안과 다른 의견 및 미정 사항

- 03번은 저장소 내부 호출만 비교하기보다 **클라이언트가 결과를 얻을 때까지의 전체 경로**를 비교해야 한다. 경로별 구간 측정은 원인 조사에 활용한다. 다른 개인 메모의 저장소 계층 직접 비교 의견과는 구분해 논의한다.
- 03번 초안의 문자열 `"0"`·`"100"`은 이후 합의한 [02번 통합 결론](../scenario_02_concurrent_counter/02-concurrent-counter-integrated-review.md)의 숫자 증감 계약과 다르다. 02번에서는 문자열을 숫자로 해석하지 않으므로 관련 내용을 맞춰야 한다.
- 비교할 DBMS, 양쪽의 구체적인 요청 경로, 데이터 보관 보장, 부하 수치, 반복 조건, 응답 시간 집계 방식과 개선 판정 기준은 미정이다.
- 이 카운터 비교만으로 API 응답 재사용의 성능을 입증하지 않는다. 해당 상황은 [04번 시나리오](../scenario_04_response_cache/04-response-cache-scenario.md)와 구분한다.
