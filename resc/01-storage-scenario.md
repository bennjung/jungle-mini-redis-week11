# 1. 외부에서 값 보관·조회·폐기

## 상태와 근거

- 사용자 시나리오의 분리는 합의되었으며, 아래 테스트 시나리오는 검토 초안이다. 개별 기대 결과와 미정 사항을 합의한 뒤 구현 계약으로 확정한다.
- 요구사항 원문: [phase.md](phase.md)의 해시 테이블 기반 저장소, 외부 사용, API 형태, 데이터 무효화, 저장·조회·삭제 단위 테스트 및 외부 사용 기능 테스트.
- 공통 개발 흐름: [AGENTS.md](../AGENTS.md).
- 이 문서는 외부 행동을 정의한다. 통신 방식, 명령 이름, 함수 인터페이스, 내부 구조를 확정하지 않는다.

## 사용자 시나리오

외부 사용자가 값을 보관하고 나중에 같은 키로 조회한다. 더 이상 유효하지 않은 값은 사용자가 삭제하여 이후 조회에서 재사용되지 않게 한다.

## 범위와 완료 판단

- 포함: 외부 저장·조회·삭제, 사용자 요청에 의한 키 무효화.
- 제외: 동시 증가, 시간 만료, 성능 우위, 장애 복구.
- 완료 판단: 합의된 저장·조회·삭제 테스트를 단위 수준과 외부 사용 경로에서 검증한다.
- 해시 테이블 사용 여부와 핵심 로직 설명 가능 여부는 행동 테스트와 별도로 확인한다.
- 이 단계만으로 읽기-수정-쓰기 경합 문제가 해결되었다고 보고하지 않는다.

## 테스트 시나리오 초안

### S1-01. 보관한 값 조회

- 사전 상태: `sample:one` 키가 없다.
- 입력·행동: `sample:one`에 값 `hello`를 저장하고, 저장 성공 응답 후 같은 키를 조회한다.
- 검증 시점: 조회 응답 수신 후.
- 기대 결과: 보관한 값 `hello`를 얻는다.
- 유지 조건: 조회가 저장된 값을 변경하지 않는다. 다시 조회해도 같은 값을 얻는다.
- 실행 범위: 외부 사용 경로. 설계 후 대응하는 단위 테스트 호출 대상을 명시한다.

### S1-02. 사용자가 값을 폐기

- 사전 상태: `sample:one`에 `hello`가 저장되어 있다.
- 입력·행동: 해당 키를 삭제하고, 삭제 성공 응답 후 같은 키를 조회한다.
- 검증 시점: 삭제 이후 조회 응답 수신 후.
- 기대 결과: 삭제한 값 `hello`가 반환되지 않으며, 값이 없음을 확인할 수 있다.
- 유지 조건: 이후 조회에서도 삭제한 값이 다시 나타나지 않는다.
- 미정: 값이 없음을 나타내는 정확한 응답과 삭제 성공 응답의 형태.

### S1-03. 다른 키에 영향을 주지 않음

- 사전 상태: `sample:one`에 `hello`, `sample:two`에 `world`가 저장되어 있다.
- 입력·행동: `sample:one`을 삭제한 뒤 `sample:two`를 조회한다.
- 검증 시점: 삭제 완료 후 다른 키의 조회 응답 수신 시.
- 기대 결과: `sample:two`의 값은 `world`이다.
- 유지 조건: 한 키의 삭제가 다른 키의 값을 변경하지 않는다.

## 계약 확정 전에 합의할 사항

- 저장 가능한 키·값의 종류와 크기, 빈 입력과 잘못된 입력 처리.
- 같은 키에 다시 저장할 때의 동작.
- 없는 키의 조회·삭제 응답, 반복 삭제 처리.
- 요청 실패 시 보장 범위와 성공·실패를 구분하는 방법.
- 위 동작을 합의한 뒤 실패·경계 테스트에 정확한 입력과 기대 결과를 추가한다.
