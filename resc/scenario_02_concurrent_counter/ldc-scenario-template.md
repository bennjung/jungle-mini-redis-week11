# 테스트 시나리오 초안 검토 메모

대상: [02-concurrent-counter-scenario.md](02-concurrent-counter-scenario.md)

## 빠진 상황

- 없는 키에 증가를 보내는 경우.
- 숫자가 아닌 값, `null`, 빈 문자열에 증가를 보내는 경우.
- `"01"`처럼 leading zero가 있는 값과 그 증가 결과의 저장 형태.
- signed 64-bit 최대·최소에서 증가·감소하는 경우.
- `INCRBY`·`DECRBY`의 `delta`가 0이거나 범위를 넘는 경우.
- `min`을 지정한 감소가 하한을 넘는 경우와, `min`을 생략했을 때의 동작.
- `max`를 지정한 증가가 상한을 넘는 경우와, `min`·`max`를 함께 지정했을 때의 규칙.
- 현재 값이 이미 `min`·`max` 밖에 있는 상태에서 증가·감소하는 경우.
- 여러 키를 동시에 증가할 때 한 키의 증가가 다른 키에 영향을 주지 않는지.
- 일부 요청이 실패했을 때 성공한 증가분이 보존되고, 실패한 요청이 상태를 바꾸지 않는지.
- 응답 유실 후 재시도로 중복 증가가 발생하는지.
- 증가와 삭제·만료가 겹치는 경우.
- 증가 명령의 저장소·HTTP 계약이 아직 없다.

## 다른 의견

- 없음.

## 미정 사항에 대한 생각

- **명령 범위** — `INCR`, `INCRBY`, `DECR`, `DECRBY` 네 개를 모두 만든다.
- **응답 형태** — `{"found": true, "value": "<새 값>"}`.
- **없는 키** — `NOT_FOUND` 404.
- **숫자가 아닌 값·`null`** — `INVALID_VALUE` 409.
- **숫자 형식** — `"01"`은 허용하고, 증가 결과는 `"2"`처럼 canonical로 저장한다.
- **범위·초과** — signed 64-bit, `OUT_OF_RANGE` 409, 기존 값 보존.
- **`delta` 검증** — 정수만 허용하고 signed 64-bit 범위를 검사한다. `INCRBY`·`DECRBY`는 양수만 받고 `DECRBY`가 내부에서 음수로 변환한다. `delta=0`은 거절한다.
- **비음수 하한** — `DECR`·`DECRBY`에 `min` 파라미터를 둔다. `현재 - delta < min`이면 `OUT_OF_RANGE` 409로 거절하고 기존 값을 보존한다. `min`을 생략하면 하한 없음(음수 허용)이 기본이다. `min`은 정수·signed 64-bit 범위로 검증한다.
- **상한(`max`)** — `INCR`·`INCRBY`에 `max` 파라미터를 둔다. `현재 + delta > max`이면 `OUT_OF_RANGE` 409로 거절하고 기존 값을 보존한다. 기본은 상한 없음. `min`과 대칭이며, 클라이언트가 GET으로 상한을 확인하는 경합을 없앤다. `max`도 정수·signed 64-bit 범위로 검증한다.
- **실패·재시도** — 멱등 키를 제안으로 포함한다. 요청 ID, 중복 요청 저장, TTL, 응답 재생이 필요하며 별도 시나리오로 둔다.
- **삭제·만료 경합** — 이번 범위에서는 제외하되, 삭제된 키의 증가는 `NOT_FOUND`로 처리한다.
- **동시성** — 단일 스레드 HTTP(`threaded=False`)로 시작한다. 저장소 자체는 스레드 세이프하지 않으며, 리뷰에서 지적이 나오면 전역 락을 검토한다.
- **오류 코드** — `INVALID_INPUT` 400, `NOT_FOUND` 404, `INVALID_VALUE` 409, `OUT_OF_RANGE` 409.
- **향후 최적화 제안** — 같은 키의 연속 +1을 큐에서 합쳐 `incr(key, N)` 한 번으로 처리하는 서버 자동 병합. 지금은 넣지 않는다.
