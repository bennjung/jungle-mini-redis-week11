# 날씨 응답 재사용 데모

Open-Meteo의 날씨 응답을 기존 Mini Redis HTTP API에 10분간 저장한다.
날씨 화면은 데모 서버가 제공하며 두 서버를 각각 실행해야 한다. 위치별
좌표는 소수점 셋째 자리로 반올림해 원본 조회와 저장 키에 함께 사용한다.
데모는 순차 요청을 보여주며 동시 요청 중복 조회 방지는 보장하지 않는다.

## 실행

프로젝트 루트에서 의존성을 `requirements-dev.txt`로 설치한 뒤,
별도 터미널 두 개에서 각각 실행한다.

```bash
.venv/bin/python app.py
```

```bash
.venv/bin/python -m uvicorn demo.weather_app:app --host 127.0.0.1 --port 8000 --workers 1
```

브라우저에서 <http://127.0.0.1:8000>을 열고 장소를 선택한다.
현재 위치는 브라우저 위치 권한이 필요하다. 권한을 거부해도 다른 장소를
선택할 수 있다. 실제 Open-Meteo 조회에는 인터넷이 필요하다.

## 발표 준비와 시연

시연할 장소의 **해당 키만** 삭제한 후 조회 버튼을 두 번 누른다.
예를 들어 서울을 선택한다면:

```bash
curl --request DELETE --get 'http://127.0.0.1:5000/kv' \
  --data-urlencode 'key=weather:37.566:126.978'
```

이 명령은 해당 키의 기존 내용을 실제로 삭제한다. 다른 장소나 현재 위치는
같은 좌표 반올림 규칙으로 대상 키를 확인한 후 삭제해야 한다. Mini Redis를
재시작하면 모든 메모리 데이터가 사라지므로 초기화 방법으로 권장하지 않는다.

날씨 데모 서버 터미널에서 첫 조회의 키 부재·원본 호출·저장 성공과
두 번째 조회의 재사용·원본 호출 횟수 유지를 확인한다. 호출 횟수는 데모
서버 프로세스가 시작된 이후의 누적 횟수다. 저장소 또는 원본 오류는
화면에 오류를 표시하고 터미널에 기록한다.

```bash
.venv/bin/python -m pytest tests/scenario_04_response_cache/test_weather_demo.py -q
```

자동 테스트의 원본은 격리되어 있으며 Open-Meteo 실서비스 가용성을
보장하지 않는다. 기존 가짜 원본 시나리오는 별도다.
